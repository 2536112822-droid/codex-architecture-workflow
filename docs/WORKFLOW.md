# 工作流与边界

这套工作流希望让 AI 帮助建筑设计逐步形成可讨论、可编辑、可核验的成果。阶段由任务深度决定：参考研习可以止于分析；概念方案可以止于空间策略；明确的局部修改不需要重走完整设计流程。

## 1. 从已有依据和当前状态开始

先读用户提供的任务书、图纸、模型和项目接续记录，再决定是否补充外部研究。对多份资料记录实际读到的范围；摘要、标题或局部截图不能代表全文已读。

接续项目时，恢复已确认决定、候选方向、已被替代的内容、未决项和实际成果位置。用户确认、助手实施、技术核验与设计认可分别记录，不凭“最终版”文件名或修改时间恢复旧决定。

对会影响成果的条件，保留三种状态：

| 状态 | 含义 | 例子 |
|---|---|---|
| 已核实事实 | 有可定位来源，适用日期与范围清楚 | 用户提供的测绘尺寸、实际模型量测、已读取的数据源 |
| 推断或设计假设 | 有依据但仍需验证，或为探索暂定 | 照片遮挡处的临时体块、未确定的开口策略 |
| 未知 | 现有证据不能建立结论 | 未测墙厚、未核实地块红线、不可见结构 |

同时区分对象的现实状态、模型表示和设计分期。模型缺件不能证明现实不存在；补全模型不自动意味着方案新建；用户选定方案不等于现实条件已验证。

## 2. 先形成可评成果，再推进依赖它的工作

每个有独立判断价值的阶段，说明要解决的问题、会展示的成果和完成依据。没有选定方向时，比较少量有实质差异的方案，解释各自的适用条件与代价；已有明确方向则继续沿用。

以下节点通常值得停下来讨论：

- 总体空间组织、活动容量与功能相邻关系。
- 入口、街巷、公共空间或关键构造的代表性样段。
- 对大量建模工作有影响的形体、开口、屋顶及衔接。
- 能确定最终表现深度和沟通方式的代表性成果。

AI 先完成适用的基本检查，给出独立判断、具体矛盾与可行调整，再提出少量会改变下一步的问题。用户主要判断设计意图与取舍，无需替 AI 做基本查错。未回复不构成选择或认可；与待定决定无关的资料准备可以继续。

已确认内容的常规生产、必要核验和明确范围内的可逆修正，不应反复要求确认。用户明确授权自行选定或连续完成时，按该授权范围执行。

## 3. 按需选择模块

```text
参考资料 / 任务书 / 现有项目
          ↓
architecture-studio：恢复状态、划分阶段、关联决定与成果
          ↓ 按当前问题选用
architecture-aesthetics：理解参考、比较方案、设计审阅
site-analysis：真实场地证据与图解
su-model 或 rhino-model：原生可编辑模型
cad-tz-model：原生图纸、标注与交付
          ↓
受影响部分的技术检查 + 视觉审阅 + 保存核验
          ↓
当前可用版本、未决项与下一阶段
```

单独建模、制图或案例学习直接使用对应模块。不要为了流程齐全同时创建 SketchUp 与 Rhino 模型，也不必为每个小任务建立项目契约或额外报告。跨阶段成果确实需要稳定交接时，才使用总控模块的版本和依赖记录。

## 4. 从设计表达转入真实模型

建模前检查已有资料是否足以说明关键几何关系。缺口影响大量后续工作时，先补一致的参考视图、可靠尺度或局部样段，解释补充的价值和消耗。优先复用已有图纸；不固定要求三视图或多轮生图。

生成图可以探索设计、辅助理解或表现已核实的模型，但不能建立实测尺寸、不可见结构或三维可用性。跨视图矛盾需要先解决受影响部分；建模后仍要用真实模型量测与必要视图检查执行结果。

几何写入前应确认目标文档、单位、坐标和当前状态，保留可恢复工作副本。写入以可核验的小批次进行；支持修订保护与幂等键的工具按其协议使用，不具备这些能力的桥接不能假定拥有相同保障。同一实时文档只允许一个自动化写入者。

超时或回执不完整时，先查活动文档和实际对象状态，再决定恢复或重试。不会因为单个工具失败就宣称整个任务不可完成，也不能靠换工具绕过原件保护、授权范围或接口限制。

## 5. 分开判断技术正确与设计表达

| 要判断的内容 | 需要的证据 |
|---|---|
| 尺寸、有效几何、闭合状态 | 原生模型或图纸的实际检查与量测 |
| 通行、活动净空、支撑关系 | 相关使用状态下的实际几何和关键路径检查 |
| 材料、层级、相机、文字与图面理解 | 适用视图和最终交付媒介的视觉审阅 |
| 独立构件是否可编辑 | 原生分组、组件、实体及实际编辑能力 |
| 文件是否可靠保存 | 实际路径、非零大小、时间或哈希；适用时重开验证 |
| 设计意图是否获认可 | 用户对该对象、版本和问题的实际反馈 |

输入尺寸不等于成品净距，包围盒不能证明完整通行，单点射线不能证明空间全部可用。图片相似不能替代几何检查；数值正确也不能证明图面易懂。缺失证据应保留为未核实。

达到本阶段用途后停止无关细化。通过的检查只在其对象未变时沿用；新改动、失败或未解决疑点才触发相关复查。

## 6. 来源变化与反馈如何传递

模型、图纸、指标和表现可能共享来源。来源包括必要脚本、参数、图像和说明依据，不能只记录主模型文件。

上游变化后，先确定具体对象、改动性质、对象对应和配准是否改变，再检查直接与间接受影响的成果。文件字节或项目修订号变化提示待核，不自动要求全部重做。相机、显示与材质变化也可能影响截图和依赖可见性的检查。

实质反馈先定位提出者、对象与版本、期望和实际表现，区分事实、设计取舍、新要求与原因假设。按具体原因修复项目或共用方法，并保留受影响成果的同步状态。规则已写、修改已实施、技术已通过和真实效果已改善是不同结论。

阶段收尾在已有项目入口简记当前可用版本、关键决定及依据、已完成检查、成果位置、未决项和下一步。阶段完成不代表整个项目完成；无需等反馈才能留下有效接续记录，也不能把沉默当作设计认可。

## 7. 审美库由使用者控制

审美库是可修订的参考知识与偏好记录，不是模型权重训练，也不会强迫每个新项目沿用同一种风格。

每轮学习先完成分析并展示成果，再让使用者一次选择：保存哪些方面、用于长期还是当前项目、属于参考知识还是候选手法或明确偏好，以及是否另行归档原件。只有收到对应本轮内容的实际选择后，才能写入长期库。

“喜欢这个案例”、此前的一次保存选择、关闭对话或无回复，都不自动授权本轮入库。不能先写进候选、收件箱或系统记忆来绕过选择。反例、案例不足及改进启示也遵循同一次范围选择。

参考知识不自动变成偏好；试做成功不自动成为用户认可。项目规则与全局偏好分开，其他项目的决定不隐式继承。完整原件只有在单独选择归档时才复制；登记网址不代表已经保存网页或取得转载权限。

## 8. 使用边界

本工作流提供设计协作方法与工具接口，不替代测绘、专业工程计算、当地现行规范核查或具有资质的专业判断。场地数据应说明来源、年份、精度与缺失项；示意分析和效果图按其实际证据范围使用。

插件安装、桥接连接、原生文件生成、技术检查和跨设备使用是不同验收层次。某一层通过不能证明其余层已通过。公开版不承诺无人干预设计或所有软件版本兼容，遇到无法验证的部分应明确说明并保留已完成成果。
