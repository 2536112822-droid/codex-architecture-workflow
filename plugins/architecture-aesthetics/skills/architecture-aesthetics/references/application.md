# 用参考增强当前设计

先弄清当前要解决的设计问题，再判断哪些历史参考有帮助。检索是线索入口，最终由模型查看相关原件并判断；关键词排序不是视觉相似度或审美排名。

先找最相关的依据；已有参考足够支撑决定就开始设计。只有检索漏掉关键关系、现有参考互相矛盾或结果不满足目标时，再扩大检索与分析。跨参考取舍使用 [analysis-comparison.md](analysis-comparison.md)，不对每个素材做完整评估。

## 形成当前项目方向

检索当前 domain 与 project，global 规则一起可用。已有项目复用 `.aesthetic/` 中记录的稳定项目名，避免同一项目因中英文改称被分成两个作用域。清楚区分已确认与候选，检查适用条件、反例和当前冲突。项目规则与长期偏好发生冲突时，先尊重当前任务及项目决定，再解释为什么；未找到合适参考时可以继续设计或有针对性补充研究。

本地检索目前是词法匹配；发现漏召回时，让主模型按实际设计问题补充少量中英同义表达，例如“材料接缝 / 材质拼缝 / material joints”，分别查询后按案例 ID/资产来源去重。需要跨媒介参考时取消 domain 过滤，但保留项目范围。结果不足时再扩展，不让首批结果成为风格上限；归档同图的不同学习批次不能算多份独立证据。没有部署图像向量服务，不把这些结果称为语义搜索。

五类学习入口帮助确定问题词，不替代应用媒介 `domain`：例如空间策略可查“公共路径 / 空间序列”，材料感知可查“接合 / 触感 / 光影”，视觉叙事可查“剖切 / 阅读层级”。旧记录未必含类别名；按关系词检索后回看实际内容，可跨类选用，不能以类别无命中认定库中没有参考。

已有案例仍不能解释关键关系、需要不同设计立场或遇到理论本身的争议时，按疑点读 [theory-methods.md](theory-methods.md) 的相关条目。参照也可以改变原问题；说明采用或搁置的具体理由，不强制调用某位建筑师，不给每个项目叠加全部理论。按任务在空间与体验判断、视觉探索、局部试作和专业检查之间往返；仅开展能推进当前疑点的工作。

案例结果中的 `excluded_rule_history` 是关联规则的否决/退役历史，按 global＋当前项目过滤。它用于理解哪些维度为何已经不适用，不能当成生效建议，也不要因为重新看到了同一案例就再次推导相同被否决方向。否决只作用于有证据的具体手法、范围和条件；保留案例的其他价值，不把整张图或所有相近风格列入黑名单。

有跨阶段一致性需求时，先在任务暂存区写 `.aesthetic/aesthetic-brief.json`；普通文件归档按全局保存策略、本任务授权和已指定或确认的位置执行。字段按任务需要而非全部强制：

```json
{
  "project": "项目名称",
  "mode": "explore",
  "intent": "本轮成果需要解决的问题与受众",
  "reference_snapshot": "references-20260909.json",
  "selected_principles": [
    {"rule_id": "规则ID", "use": "当前如何转译", "reason": "适用理由"}
  ],
  "creative_space": ["本轮可主动探索的内容"],
  "source_locks": [],
  "facts": [],
  "unknowns": [],
  "deliverables": ["本轮实际需要的成果"],
  "verification": ["与改动风险相称的验收证据"]
}
```

`mode` 可为 `explore` / `refine` / `review`，描述当前授权，不是额外权限开关。`source_locks` 每项写内容、依据和验证方式；仅固定已确认且本轮需要保持的部分。新的设计探索可不锁旧形体；仅调整已确认模型的材质时应保护几何。

用 `snapshot` 保存相关记录和版本；它只冻结参考检索结果，不自动完成上述设计选择或精度验证。旧项目已使用的快照保留，新轮次另存。现有 architecture-studio 项目 schema 顶层不接受额外字段；将本文件作为独立附件并在允许的 artifacts/qa/evidence 中引用。

## 跨媒介转译

颜色、节奏、主次关系、材质逻辑可以转译；每个媒介仍解决自己的问题。例如借渲染图的主次关系来组织 PPT 叙事，不把照片的景深模糊转成图纸底图。优先保持整套成果的术语、颜色语义、视图和材料命名一致，允许不同媒介有不同表达强度。

摄影可提供光线层次，书籍提供信息节奏，展览提供空间与观看顺序，地图提供图例语义。写清“来源中的关系→当前问题→采用方式→不能照搬的部分”。具体能力与工具选型见 [crossdomain.md](crossdomain.md)。项目已有方向需要一致性时，记录可替换的颜色角色、文字层级和间距；这些服务于该项目，不把多个项目平均成固定风格包。

PPT 交给 presentations，明确内容、数据、页序、可编辑性和希望改善的叙事/版式；材质与场景交给 su-model/rhino-model；标准绘图交给 cad-tz-model；参考风格组合或图像表达可复用 creative-production。只在任务确实横跨多个阶段时调用 architecture-studio 协調。

按成果寻找最值得改善的一环：

| 成果 | 优先分析与参考对比 | 修改方向与相应核验 |
|---|---|---|
| PPT/作品集 | 观众能否跟上论点、图像是否解释文字，比较页序与阅读路径 | 先解决信息主次，再处理字体/留白等局部；按改动检查实际渲染和编辑对象 |
| 模型质感 | 纹理尺度、方向、分缝、厚度和光照谁在主导效果 | 根据成因调整材质/UV、相关细部或场景，复核本轮需保护的几何与保存状态 |
| 渲染 | 材质是否可辨、光影和接触是否可信，参考优势是否只是曝光或镜头不同 | 围绕具体问题使用参考，改善后回看对应部位；保真任务核对源图/模型，开放探索保留创造空间 |
| CAD图面 | 阅读层级问题还是单位、尺寸、关联或标准问题 | 表达问题改善组织与注释，技术问题交原生工具量测；图像相似不作为标准证明 |
| 方案设计 | 思路怎样回应问题、形成空间组织和体验，具体策略有何巧妙与代价 | 按 [design-ideas.md](design-ideas.md) 转译有效关系，结合当前条件重新构成；思路价值和外观表达分别判断 |

上述是定位主要问题的入口，不是每项交付都要跑的审查表。明确的小改直接完成。

图板或演示页存在具体的间距、裁切、对比度或色阶问题时，选读 [graphic-diagnostics.md](graphic-diagnostics.md)；保留当前风格与原生交付格式，不因采用某种检查改成另一种模板或文件类型。

## 主模型与图像工具协作

主模型负责读取多模态证据、提出并比较设计解释、解决参考之间的矛盾、选择具体实现、操作专业工具及复核。提供目标与依据，避免写死推理步骤、固定风格词和候选数量。模型可以创造参考库中没有的新组合，并说明为何更适合本项目。

图像生成/编辑采用当前可用 imagegen 工具，读取其技能和接口。工具可支持多个图像时，为每张输入说明角色：源模型/构图、材质、光线、氛围等，避免不加区分地混用。不要把全部案例库提交给图像模型；按任务选择足够有效的参考。

给图像模型一个连贯视觉简报：成果目标、参考分工、相关必须保留内容、开放设计空间、想解决的实际问题。让它决定适合的细节、表面变化、灯光关系和构图处理。局部修改优先使用最相关已查看原图；开放探索允许新的设计构成。只有实际接口暴露时才设置模型、尺寸、质量、mask 或其他参数。

将比较得到的有效关系和明确不迁移部分交给图像模型，不把整份分析报告或彼此冲突的风格词都塞入提示。控制项服务于真实任务；说明目标后，允许模型自主解决未指定的细节。已有图像满足要求时不为凑“更优版本”继续生成。

调用前区分用户要求的模型、接口可提交的模型参数和服务实际返回的模型信息。依据本轮 schema 与当前官方资料核实精确模型标识；没有模型参数时，不能通过提示词强制选模，也不能承诺指定后端已启用。工具/源码中的默认标签、文件名、图片 C2PA 或其他元数据不单独证明后端版本；文档存在冲突时保留未知并说明来源，不把推断写成事实。

用户未要求精确选模时，沿用已授权默认路径，无须为记录再次询问。精确要求无法满足时，先完成独立准备，说明缺口；仅缺少会改变处理的替代选择时询问一次，已有替代授权则直接沿用。不得静默换模型或转到单独计费的 API；确认 API 路径后优先复用官方现有 CLI/SDK，不为选模另造插件，也不修改 bundled 生图脚本。CLI 接受参数或 dry-run 成功仅证明请求构造，不能证明账户权限、后端执行或质量提升。

正式图像成果需要溯源时，在已有 manifest/进度中保留调用路径、请求模型、提交参数、回执所报模型（未提供则 unknown）、调用/回执位置，并关联基图或模型修订与输出文件；不要用提交参数填充回执字段。复用已有记录，不强制每张图另建报告，不记录密钥或整段图片编码。若回执与请求不同，标明差异再核对；超时先查回执和输出状态，不自动降级或盲目重试。模型和推理设置同样由实际界面/配置控制。

对几何精度要求高的最终表现，从真实模型取得可信基础视图。生成条件和视觉对照能降低漂移风险，不能取代模型测量。发现门窗、屋顶、结构变化时，将它标记为新的设计提案或返回修复，不把它默认为原方案准确表现。

## 判断完成

验证本次真正改变的内容和受影响对象。已足够满足目标时交付；有具体问题才迭代，不以自评分升高为理由无限生成。需要比较方案时使用有意义的不同方向，而不是强制凑变体。

记录本项目选用原则、关键取舍、修改前后对应视图/页面以及尚未核实部分。只报告通过的实际检查，不用“图很漂亮”替代 CAD 尺寸、源信息和文件保存状态。用户后续反馈先用于本次改进；需要学习并持久化时，回到 learning.md 的分析后保存选择。未经该次确认，不回写个人库。
