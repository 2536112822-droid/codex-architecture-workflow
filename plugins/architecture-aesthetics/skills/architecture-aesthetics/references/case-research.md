# 按需补充案例的现实资料

仅在判断补查对本轮学习有价值时使用。搜索服务于理解案例，不是每个案例的固定前置步骤，也不以资料或链接数量衡量分析深度。

## 围绕值得弄清的问题查

先读用户已提供的资料，再结合资料完整程度、学习重点和设计深度决定是否补查。完整度相对于当前问题判断：一张图可能足以学习构图，多张渲染也可能无法解释建筑的剖面组织。设计深度看有无值得追溯的空间、技术、文化等关系，不按项目名气、规模或造型复杂程度判断。

需要补查时围绕具体问题选资料，例如：场地条件怎样促成设计；平剖面能否说明公共路径；结构与材料怎样实现概念；建成或使用后的情况是否支持设计主张。这些是可选方向，不是必查清单。用户只研究局部时不擅自扩展成整栋建筑调查；用户限制联网或来源范围时遵从。

在来源足以支撑本轮理解、进一步检索主要得到重复内容时收束。缺少关键资料时，先尝试与缺口相关的原始来源、项目别名或当地语言关键词；适用路径仍取不到就说明缺项，继续完成其他分析，不无限追查，也不把无结果当作资料不存在或设计失败。

## 确认查到的是哪个项目

结合现有名称、设计者、地点、年代/阶段和图面特征判断归属；同名或外观相似不足以合并。区分竞赛、未建方案、竣工、改造及运营阶段，不把效果图当作建成照片，不把旧开放信息当成当前状态。

身份仍不确定时，将候选来源与原案例分开。可以围绕可见设计策略查询相关建成先例或一般背景，但必须标为“对照案例/背景”，不能代替原案例事实。确需项目名或链接才能回答关键问题时才询问缺项，其余学习继续。无需为常规检索请求许可，也不得擅自上传私人图纸或图片做反向搜索。

## 选择并实际读取来源

优先找与问题相符的一手资料：设计者或业主的项目档案、原始平剖面与说明、规划/公共机构记录、工程团队的技术资料、运营方信息、研究论文及使用后评价。专业媒体可补充图纸、采访或提供原始出处线索；转载同一稿件不算独立印证。

使用当前可用的网页搜索和读取工具，实际打开相关页面、文档或图纸。搜索摘要只作定位线索；打开成功不等于读到正文，文字提取不等于看过图纸。多来源任务沿用已有证据记录，简记标题/机构或作者、URL、已知发布日期或版本、实际读到的页/段/图及缺项；动态事实另记查阅日期，日期不明就注明，不凭空补齐。简单分析用贴近结论的链接与必要限定即可，无需另造来源表。

抓取没有取得所需内容时，按全局工具恢复规则检查并尝试适用的真实浏览器；需桌面交互时再读 Computer Use 技能。说明实际受限环节，不将一种工具失败当成所有途径不可访问；不绕过认证或网站限制。

## 用资料深化或修正分析

把补充资料放回它所解释的设计关系，说明它补足、支持或修正了什么，以及对迁移的影响。不要只附一串链接；外部材料更丰富也不直接证明方案更好。

- 作者文字支持“作者提出这一意图/主张”，不能单独证明体验、环境或社会成效已经实现。
- 图纸支持其可见空间与构造关系；建成影像支持所见状态。实际开放、使用体验、性能或维护表现需对应运营、调查或测量依据，并保留适用时段与条件。
- 沿用 `fact / inference / unknown`：来源直接支持的事实、模型解释与尚未知部分分别表述。专业审美判断不因有链接就自动升级成事实。
- 来源矛盾时核对项目身份、版本、阶段及口径，保留无法消除的差异。未建方案按思想与实现条件分析，不强求不存在的使用后证据。

新证据推翻旧解释时，明确修正受影响结论与迁移建议；复用未受影响的观察。若仍未核实，只限制依赖该事实的部分。

## 沿用现有保存选择与字段

检索和阅读不等于获准入库。将补查形成的分析与本轮其他成果一起展示，按原有规则取得实际保存选择；网页、图片或原始文件的完整归档仍独立于文字成果保存。

获准保存后沿用 [library-cli.md](library-cli.md)，无需新增字段：主来源放 `case.url`，`case.source_note` 只写中性定位；各所选方面的结论放 `observations[].text`，对应的直接 URL、来源名称、日期/版本和实际读取位置放 `observations[].evidence`，证据状态放 `certainty`，缺项或冲突放 `limitations`。来源支持的是作者主张时，在结论文字中保留“作者称”。不要把整轮来源摘要或未选成果塞入不会按方面筛选的 `source_note`；来源证据随各方面的保存选择保留。仅存链接不能声称已归档网页或图片。
