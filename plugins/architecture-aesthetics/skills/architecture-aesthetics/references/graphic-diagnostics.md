# 图板与演示页的局部诊断

仅在相关问题影响当前成果时选用对应部分。此处提供测量与修正依据，不定义统一风格、色数、网格、字号、像素间距或审美分数；用户选择的高饱和、非对称、密集表达仍然有效。原生编辑、渲染与可编辑性检查继续交给对应专业技能。

## 间距、边界与信息关系

- 先辨认标题、证据图、图注、图例属于哪个内容组，核对标题、结论与证据图的含义是否一致，再判断组内距离、组间距离与页面边界是否表达了关系。图文自相矛盾是表达问题，不必等外部事实核查才指出。同类模块检查共同对齐线和间距的一致性；为叙事而设置的偏离可以保留，不把所有对象强行均分或居中。
- 将问题定位到实际页和对象：越过哪条内容边界、图注被谁遮挡、裁切丢了哪部分信息、图文是否需要共用顶部/底部基线。能读取布局值时测量对应边界与实际溢出量，不能量得就说明仅为视觉观察，不编造数值。
- 局部溢出优先调整对应对象的间距、换行或可用区域；改变布局或拆页取决于内容密度。不能为了消除溢出删除必须内容、缩到实际观看时无法阅读，或裁掉图纸/照片中的证据。处理后查看受影响页面的真实渲染，兼查修正是否造成遮挡、无意空洞或新的阅读顺序问题。
- HTML 可读取 DOM 边界；PPT 使用原生对象与实际渲染；打印图板按物理纸幅与比例检查。不要把网页 px、固定模板的布局白名单或裁切比例当成跨媒介标准。

## 颜色与图例

- 先区分颜色的职责：文字/背景、类别、连续数值、围绕中点的偏差、强调或装饰。保留项目语义、数据范围、单位、图例及必要标签；类别不能只靠颜色辨认时补文字、线型或符号。
- 对比度计算需要明确的前景与实际背景颜色。照片、渐变、透明叠色和未知背景不能用一个猜测的底色代表整块区域；可逐区域取实际证据，或调整局部文字承载方式后再查。无法可靠取值就保留 unknown。
- 屏幕文字可借鉴 WCAG 2.2 AA：普通文字 4.5:1、大字 3:1；采用前确认字号与媒介，明确作为标准要求还是项目参考。数值只证明该颜色组合在所选阈值下的结果，不代表整体无障碍、打印/投影可读或审美合格。不能靠显示值四舍五入让临界失败变通过。
- 对有序数值色阶，检查预期明暗方向是否出现反转；类别色与两侧发散色阶不能套用全序列单调检查。相对亮度单调仍不证明感知步长均匀、色觉可分或数据映射正确。需要生成复杂色阶时，优先复用项目已有工具；Chroma.js 是可选项目依赖，不作为本技能启动条件或全局安装要求。

## 可选的本地数值助手

有明确不透明 sRGB 色值且需要计算时，可运行本技能的 `scripts/color_audit.py`（Python 标准库，无额外依赖）。它只读输入、输出 JSON，不抓取截图、不改颜色、不写作品、不连接审美库。

```powershell
python -B <skill-root>/scripts/color_audit.py --foreground '#AAAAAA' --background '#FFFFFF' --minimum 4.5
python -B <skill-root>/scripts/color_audit.py --input <task-work>/colors.json
```

`python` 若指向占位别名，使用当前已确认的真实解释器。输入示例（只填当前有依据的项目）：

```json
{
  "pairs": [{"id": "p2-caption", "foreground": "#AAAAAA", "background": "#FFFFFF", "minimum": 4.5}],
  "ramps": [{"id": "height-legend", "colors": ["#F4F0FF", "#A88BCD", "#553078"], "kind": "sequential", "direction": "decreasing"}]
}
```

只接受 `#RGB` / `#RRGGBB`。`minimum` 可省略，此时只报比值、不判通过；只有显式声明 `sequential` 与方向才做明暗顺序检查，`categorical` / `diverging` 不采用该门槛。退出码 0 表示有效输入没有触发已声明检查的失败，1 表示有失败，2 表示输入无效；任何退出码都不是美学认证。临时输入与结果按当前任务暂存策略处理。

## 采用改动的依据

优化已有成果时，以同一内容、输出尺寸和观看条件比较对应页面：问题是否改善，关键信息、已有风格、阅读路径及原生可编辑性是否保留。只有局部修正有明确收益时才采用；出现退步则回到原方案或保留待选候选，证据不足时不以“更高级”替代验证。开放探索仍允许新的构成，不把这条比较规则变成冻结原设计的理由。

## 方法来源与适用边界

2026-09-19 核对：借鉴以下方法并按建筑表达重新表述，不复制其模板、强制布局或品牌样式。

- [Guizang PPT 检查清单](https://github.com/op7418/guizang-ppt-skill/blob/main/references/checklist.md)：可定位的边界、图文关系与实际渲染检查；其 HTML 模板不替代 PPTX。
- [Carbon spacing](https://carbondesignsystem.com/elements/spacing/overview/) 与 [2x Grid](https://carbondesignsystem.com/elements/2x-grid/overview/)：间距表达内容关系、共同对齐基准；不移植固定像素值。
- [Chroma.js](https://gka.github.io/chroma.js/)：颜色计算、色阶与感知空间；本助手仅实现公开的相对亮度/对比公式，不复制该库，也不提供感知均匀性保证。
- [W3C WCAG 2.2 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：屏幕文字阈值、实际字体与抗锯齿等限制；不推广为建筑材料、艺术图像或所有媒介的硬标准。
