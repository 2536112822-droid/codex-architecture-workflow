# 参数化二维构件

仅在用户需要规则排孔板、开孔面板等重复修改的二维构件时使用。普通建筑制图继续走现有 `cad_apply_plan`；三维构件和 Grasshopper 任务继续使用对应专业工具。无需安装 text-to-cad、cadgen 或新的 CAD 内核。

## 参数源与模板

`scripts/panel_plan.py` 使用 Python 标准库，将明确参数转换为现有 plan 支持的矩形和圆。示例参数在 `assets/panel-parameters.json`；将它复制到已授权的项目或任务暂存区后修改，保留作为尺寸来源。

```text
python <skill>/scripts/panel_plan.py --params <panel-parameters.json> --out <new-panel-template.json>
```

不传 `--out` 时只输出 JSON；传入时只允许创建新文件，拒绝覆盖。生成器不连接 AutoCAD，不启动程序、不创建实体，也不生成 DXF/DWG 文件。

- `unit` 明确为 `mm`、`cm` 或 `m`。所有长度和 `origin` 均使用该单位；改变单位标签不等于数值换算。
- `offset_x`、`offset_y` 是板左下边到第一个孔心的距离；`pitch_x`、`pitch_y` 是孔心间距。
- `min_edge_clearance` 与 `min_hole_clearance` 是本构件明确要求的最小边缘余量、孔间净距。它们必须来自用户/项目要求，或作为待核实的建模假设；示例值不是加工标准。
- 生成器拒绝非法/非有限数值、越界/相切/重叠孔、余量不足及超过桥接批量上限的计划。`checks` 中的数值只证明模板中的二维几何关系，未检查材料、结构、刀缝、打印和施工规范。

输出是 `kind: cad_plan_template` 的封装。`plan` 才是待绑定的计划；`parameters`、参数指纹和生成器版本用来记录来源。保留参数源、计划与最终图纸之间的对应关系，不把导出的 DWG/DXF 当作仍保有自动参数联动的源程序。

## 进入现有制图闭环

1. 审核生成的坐标、孔数、尺寸、净距与图层；确认模板符合当前二维构件范围。
2. 按原技能锁定实例、创建必要工作副本、读取最新 `cad_state`。在 `plan` 中绑定真实 `expected_document_id`、`expected_revision` 与本次计划版本独有的 `idempotency_key`；生成器不提供这些值。
3. 首次采用该模板或几何/接口仍不确定时，按原规则先做独立 dry-run，再通过 `cad_apply_plan` 提交。检查其返回的实际几何 QA、必要视图和保存文件；模板检查不能代替它们。
4. `operations.id` 只映射返回结果，**不是更新已有实体的标识**。用新 key 再提交会新增实体。修改已经画好的构件时，先查询并核对旧 handles，按原 `cad_edit` 流程最小修改，或在明确替换范围内使用受保护的新计划；不得因参数改变自动删除原构件。参数哈希也不是提交幂等键。
5. 超时后按原键、原计划和原保护值处理重试，不重新生成 key；这由现有桥接协议管理。

## 制作与导出边界

模板给出的是二维板外轮廓和孔轮廓，不是三维实体挖孔。若用于激光切割，须在实际导出的文件里检查单位、闭环、重复线和切割层，再按所选材料/加工商的现行要求核查；若用于打印，需另建三维模型并检查缩尺后实际输出的壁厚。本辅助脚本不签发制造通过结论。

此增量借鉴 text-to-cad 0.6.5 的“参数源—输出—检查”组织方式，继续沿用本机真实 CAD 实体、事务、版本保护和保存流程。
