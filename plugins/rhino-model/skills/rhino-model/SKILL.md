# Rhino + Grasshopper 建模

## 文件保存与收尾

文件暂存、正式保存、中间数据保留与清理遵循当前全局 AGENTS.md 和本任务已有授权。已有授权或默认策略覆盖的事项直接执行，只询问仍缺少的必要决定；本节优先于下文及参考文件中的保存和保留默认值。


产出应当可编辑、可量测、可局部修改，并同时经过数值与视觉验证。几何操作优先使用 RhinoMCP 的结构化工具；Computer Use 只负责桌面应用生命周期、Rhino 命令栏、交互对话框和可靠保存。

## 启动与目标锁定

当任务需要启动、连接或排障时，先阅读 [本机运行时](references/local-runtime.md)，必要时运行只读的 `scripts/preflight.ps1`。

1. 先尝试 `get_document_summary`。连接失败时才用 Computer Use 启动已安装的 Rhino，避免反复重启。
2. 从 Computer Use 返回的窗口中唯一选定目标 Rhino。存在多个候选窗口、文档或端口归属不清时，不得猜测或写入。
3. 记录任务开始时端口是否已监听，以及本任务是否执行了 `MCPStart`。仅在端口未监听时，在已核对窗口的命令栏启动；观察到服务启动后再调用 `describe_capabilities` 与 `get_document_summary`。
4. 记录文档名/路径、单位、公差、对象数、图层层级、模型包围盒和目标 GUID，作为本批操作的状态指纹。
5. 若此任务刚完成安装或升级，且当前授权包含临时几何测试，可在已核对的临时文档中运行一次烟雾测试；测试对象唯一命名并按返回 GUID 清理。授权未覆盖几何写入时才请求确认。

若 Rhino MCP 工具在当前 Codex 任务中尚未出现，先按工具名称和能力检查当前目录及可用的工具发现/加载入口，区分未安装、未启用、会话未注册和桥接未连接。仅在确认工具已安装启用、当前会话无法加载且需要重新拾取时，才说明需要新建 Codex 任务；不要通过反复重启 Rhino 解决工具注册问题，也不为恢复连接启用被禁用的任意执行接口。

## 建模闭环

1. 在写入前明确当前单位、坐标/CPlane、图层、尺寸、几何关系和仍未知的假设；所有长度按当前文档单位解释。
2. 调用 `get_document_summary` 及必要的 `get_objects` / `get_object_info`，确认是在新建、修改还是替换。
3. 除已获确认的临时烟雾测试外，首次几何写入前先在本任务暂存区确定不冲突的版本化 `.3dm` 工作路径，用 Computer Use 另存工作副本。记录源文件 hash/mtime，确认活动文档已切换到副本且源文件未变，再改副本；若用户明确要求原位修改，也先建立可恢复备份。
4. 参考驱动任务先明确采用方案及各参考的对象/版本、可读性、比例/透视与未知尺寸；同一方案可由图纸、可靠尺度和多视图互补，分清整体控制与局部补充，解决影响建模的矛盾。按需补参考以提高建模前细节转译，先说明价值/消耗，不固定生图或视图数量。尺寸关键任务缺少必要约束时先查已有依据，再请求真正缺失的尺寸/控制线；标明假设的独立概念试做可继续。
5. 先建图层，再以可核查的小批次建模。语义重要的对象优先逐个创建并赋唯一名称；保留每个返回的 GUID 和包围盒。
6. 曲面与实体优先使用 `loft`、`extrude_curve`、`sweep1`、`offset_curve`、`pipe`、布尔运算及曲线投影/相交/分割等专用工具，不用任意命令或代码执行绕过结构化接口。
7. `modify_object` 无法表达的 NURBS 控制点形变，应从明确点阵/控制线重建候选曲面。先保留旧对象，验证候选后迁移图层、名称、材质与属性，再按旧 GUID 精确替换；不能验证时停止。
8. 每个实际修改阶段后核对活动文档路径、状态指纹和目标 GUID，按变化选择 `get_object_info`、`analyze_objects`、`measure_objects` 或文档摘要，验证相关的有效性、闭合/实体状态、尺寸与对象属性。同一状态下复用已取得的证据；非目标对象与属性应保持不变。
9. 需要视觉判断时，复用有效图像，按问题用 `capture_viewport` 或 Computer Use 截图取得必要视图，不重复抓同一证据。直接保真对比尽量匹配投影、相机和裁切；不能匹配时说明定性比较范围，尺寸用实际几何核验。包围盒距离只能作为近似值，临时视图检查后恢复需保留的相机状态。
10. 超时或结果不明时先重新查询活动路径、对象数和 GUID；不得盲目重放写操作。错误修复只针对已记录的 GUID。

## Grasshopper

- 先读取 `gh_get_document_info`、`gh_get_canvas_state` 或 `gh_get_graph`。
- 优先用 `gh_build_graph` / `gh_mutate_graph` 分阶段构建，再运行 `gh_run_solution` 并检查图结构、参数输出和预览。
- Grasshopper 没有 Rhino 数据库式事务；一次只提交一个可验证阶段。
- 清空画布/图、删除既有组件或覆盖 GH 文件前，必须确认范围并先保存可恢复副本。

## 保存、交付与收尾

保存和完成前按 [质量门](references/quality-gates.md) 检查。

1. 当前 RhinoMCP 没有安全的高层保存工具；用 Computer Use 操作 Rhino 的“另存为（`SaveAs`）/保存副本（`SaveACopy`）”，记录实际保存方式及选项，并在每次对话框返回后重新核对活动文档路径。授权原位保存时仍须保留修改前的可恢复备份。
2. 核验暂存工作副本后，按全局保存策略和本任务授权向已指定或确认的目录保存正式 `.3dm` 并展示结果；不默认覆盖原文件；已有替换授权不重复索取，遵守当前 Computer Use 要求。
3. 等保存完成后按实际方式核验：普通 `SaveAs` 要求活动路径等于输出路径；`SaveACopy` 保持原活动文档，不因此判定失败或重复保存。`GeometryOnly` 类似几何导出，不切换活动模型且不保留图层、材质、属性、注释及单位设置，不能作为完整文档交付或可恢复完整副本，除非任务明确只需这种几何输出；见 [Rhino 保存行为](https://docs.mcneel.com/rhino/8/help/en-us/commands/save.htm)。输出均须实际存在、大小非零，并核对修改时间；重要交付记录 SHA-256。复制交付须确认源文件 hash/mtime 未变；授权原位修改则验证输出及修改前备份，不要求源文件保持旧 hash。条件允许时在不干扰活动文档的前提下重开副本验证，否则明确标注未重开验证。
4. 报告单位、对象/图层概况、关键 GUID、QA 结果、保存路径和未确认假设。
5. 只有当本任务启动了 MCP 且没有共享使用者时，才在同一 Rhino 窗口执行 `MCPStop` 并确认端口不再监听；若复用了既有桥接，则保持运行并明确报告。默认保留 Rhino 窗口供用户检查；仅在窗口由本次任务创建且为空或已可靠保存时关闭。

## 安全边界

- 始终保持回环地址、禁止远程连接和严格 schema 校验。
- 保持 `run_command`、`execute_rhinoscript_python_code`、`execute_rhinocommon_csharp_code` 禁用；普通建模任务不得临时放开。
- RhinoMCP 0.3.2 没有文档 revision 或写入幂等键。同一文档只允许一个自动化写入者，并行代理不得同时改模型。
- `undo` 不能作为唯一回滚手段；保留写入返回的 GUID，并用精确删除或最小修复收尾。禁止为清理测试使用 `delete_object(all=true)`。
- 用户手工修改、切换文档或响应超时后，必须重新读取状态。停止 MCP 不等于保存文件，有未保存的用户修改时不得关闭 Rhino。
- `capture_viewport` 若切换视图或缩放会改变相机状态；需要保护既有视图时先记录并在检查后恢复。
- Computer Use 仅控制 Rhino/Grasshopper UI；不得用于终端、Codex、安全设置或登录界面，并应遵守其确认规则。
