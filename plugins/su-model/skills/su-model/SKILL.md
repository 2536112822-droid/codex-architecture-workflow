# SketchUp 建筑建模

## 文件保存与收尾

文件暂存、正式保存、中间数据保留与清理遵循当前全局 AGENTS.md 和本任务已有授权。已有授权或默认策略覆盖的事项直接执行，只询问仍缺少的必要决定；本节优先于下文及参考文件中的保存和保留默认值。


目标不是一次性“画出像样的图”，而是建立可编辑、带稳定语义 ID、能量测和能局部回改的 SketchUp 模型。优先使用 `su_apply_plan`；`su_eval` 只作为结构化工具暂未覆盖时的专家兜底。

## 启动与目标锁定

1. 首次连接调用 `su_ping`、`su_capabilities` 和 `su_info`。同一连接内可复用能力信息；重连、升级或能力变化时重查。活动模型身份与 revision 不可当作静态能力缓存。
2. 连接失败时先区分工具未注册与应用/桥接未启动：前者先检查当前及可发现工具；后者先阅读可用的 Computer Use 技能，检查现有 SketchUp 窗口，在目标唯一明确时启动已安装的软件，并操作“扩展程序 → SU AI 建模 → 一键启动”。新建/打开模型须符合当前任务，不丢弃已有未保存内容，不反复重启。每次实际恢复后重新调用 `su_ping`、`su_capabilities` 和 `su_info`；只有自动恢复不可行、目标不明或必须人工操作时，才说明具体阻塞并请用户协助。
3. 写入前记录 `model_token`、`revision` 和显示单位。若活动模型或修订发生变化，重新检查，不得沿用旧计划。
4. 环境首次启用或升级后运行 `su_selftest`。自检几何会回滚，不污染用户模型。

## 建模闭环

1. 把简报拆成层级、构件、尺寸、材质和未知项。所有长度显式使用 `mm/cm/m/in/ft`；SketchUp 内部裸数是英寸，禁止把裸数当成显示单位。
2. 用户提供图片时，先用 `view_image` 原始精度检查透视、遮挡、尺度锚点与不确定信息；至少需要一个可靠尺寸才能做尺度复刻。
3. 调用 `su_inspect_model`，用已有 `spec_id`/`persistent_id` 判断是新建、修改还是删除。不要仅依赖实体名称。
4. 构造带 `expected_revision` 与唯一 `idempotency_key` 的 `su_apply_plan`。一次提交一个可验证阶段，例如体块、围护、开口、楼板、屋顶或材质。
5. 每次提交先检查返回状态与新 revision，按变更范围核对目标构件。几何或语义变化时运行相关 inspect/validate 检查；整体范围变化可用 `su_bounds` 量测，但包围盒或建模输入不证明成品净距。涉及通行/活动时按 [质量门的空间使用检查](references/quality-gates.md) 核对实际路径、相关状态与必要净空。异常或响应不完整时扩大检查，最终交付前完成与请求范围相符的验证；记录已有无关缺陷，不擅自扩展为全模型修复。
6. 复用有效视图，必要时用 `su_capture_views` 从 `iso/front/back/left/right/top` 中选择能回答本次问题的视图；支持且有需要时补局部剖切/量测。用 `view_image` 检查遮挡、穿插、缺件、相机、材质及设计关系是否易辨；不固定凑齐视图，也不把补视图自动变成生图任务。
7. 发现问题时只提交最小修正计划，复查受影响的数值与视图；家具或小组件效果不足时，按下文“家具与小组件的改进选择”决定修正、自建或引入素材。已通过且对应状态未变的证据可复用。不得为了局部错误整模型重建。
8. 在任务暂存区完成必要的 SKP 工作副本保存与验证；按全局保存策略和本任务授权，用 `su_save` 写入已指定或确认的路径并展示结果。不覆盖原 SKP，除非已明确授权。

结构化操作字段和示例见 [structured-plan.md](references/structured-plan.md)，验收门见 [quality-gates.md](references/quality-gates.md)。

## 建筑语义

每个可编辑构件都应附带：

```json
{
  "spec_id": "L01-WALL-EXT-001",
  "kind": "external_wall",
  "level": "L01",
  "certainty": "confirmed",
  "source": "user-brief-v2"
}
```

`spec_id` 在项目中必须唯一并保持稳定。区分 `confirmed`、`inferred` 和 `unknown`；从参考图推测出的尺寸不可伪装成用户确认值。

`certainty` 必须说明确认的是哪项主张；用户确认方案或几何保留检查通过，不能确认现实状态。对本次关键/变化对象，在既有记录中另辨几何来源及日期、现实证据、模型表示（如补全/隐藏）和方案分期；补建网格不自动属于方案新建，未显示也不等于现实不存在。不要求给全部旧构件补属性，不向工具传入未支持的字段。新基底先核对改动对象及配准，再局部传播；没有可靠转换时保留近似状态，不擅自拉伸已确认构件来贴合背景。

## 分组与可编辑交付

- 按实际独立编辑单元建立有意义名称的组或组件，例如墙体、楼板、屋顶、门窗、楼梯。线面保留在所属构件内，不把完整模型炸成散乱线面，也不机械地逐线逐面分组；Tag 不能替代几何分组。
- 完整建筑成果保留可分别选择、进入编辑的构件组。交付时不额外把整套模型包进一个总组，也不将本应独立编辑的构件融合在一个组内。允许按建筑、楼层或功能保留有实际用途的父组，避免无意义套组；不硬性规定顶层组数或嵌套层数。
- 重复构件在需要联动修改时使用组件；需要独立变化的实例先设为独立组件或采用组。避免意外锁定，保留用户明确设置的保护与联动关系。
- 修改已有模型时保留用户确认的合理层级，只在本次范围内调整。整理多余外壳时保留内部构件分组及其位置、材质、Tag 和语义属性，不递归炸开。交付前按 [quality-gates.md](references/quality-gates.md) 检查分组及实际可编辑性。

## 家具与小组件的改进选择

- 先从实际交付视角判断问题来源。比例、摆放、材质或局部细节不当时，优先修正现有组件；若问题来自照明或相机，修正相应视觉设置，不盲目替换几何。
- 普通成品家具、复杂曲面椅子、灯具等，若成熟素材能更有效改善表现，主动联网寻找合适的现成模型并在可获取、可导入时采用，无需先反复自建到失败。结合项目风格、画面重要性、精度需求和模型负担选择，不为每个小件固定执行搜索。
- 影响空间设计的定制家具、固定装置，按方案继续建模，或以合适素材为基础改造；不得为了适应素材而改变已确认的建筑几何与布局。
- 引入前核对来源与使用许可、格式兼容性、真实尺寸、风格、面数和贴图负担；下载候选放入本任务暂存区。无法获得可用素材时说明限制，转为自建或适度简化，不把找到预览图当作已取得可用模型。
- 导入后检查尺度、材质与贴图、位置、穿插及实际视角下的表现，保留有用的组/组件和内部构件层级，确认可进入编辑及共享实例的联动符合意图。替换只作用于本次目标，遵守上文分组规则；记录采用素材的来源及必要依赖，纳入交付核验和收尾选择。
- 达到当前视距与交付精度后停止细化。以整体方案表达和可编辑性为准，不因无关紧要的小配件无限打磨，也不把高面数或精美预览等同于实际改善。

## 图像到模型

- 先确定原图类型：透视照片、正投影图、平面图、立面图或效果图。透视图不能直接当作无畸变尺寸底图。
- 建模前若关键形体、屋顶/跨数、开口或衔接不清，按需补一致的参考视图或局部细节，帮助更细致、准确地转成几何；这与建模后抓取多视图核验执行结果是两个用途。先说明补哪处、解决什么和预计消耗，优先复用已有图纸/尺寸，不固定三视图或反复生图。
- 多张参考须对应同一采用方案、对象、朝向及可靠尺度锚点，分清整体控制与局部补充。跨视图矛盾先解决受影响部分，生成图不能使未知尺寸/结构变成实测事实。转译疑点会导致大量返工时，先建代表性体块/接口，核对关键关系和实际量测，在需要设计取舍的节点讨论后再批量深化；常规可靠操作不增加确认。
- 可运行 `scripts/measure_image.py` 提取宽高比、主色和边缘分布；这些只用于辅助定位，不能替代尺度锚点。
- 先建低细节 massing 并锁定整体长宽高，再逐层补墙体、开口、楼板、屋顶和固定构件。
- 关键视角需尽量匹配参考图；必要时运行 `scripts/compare_images.py` 生成并排/叠加对比，但最终仍要用模型量测确认。
- 无法从图中确定的背面、厚度或层高标为 `unknown`，采用临时假设时写入 `source` 并向用户说明。

## 表现图

1. 用 `su_render` 导出无边线、带材质的干净 PNG；该操作会恢复原相机、阴影、样式和边线状态。
2. 先保留一张结构清晰的原始 SU 图作为几何基准。
3. 默认使用 Codex 原生 ImageGen，以 SU 图作为结构参考生成外观变体；明确要求保持体量、开口、层数和相机，只改变材质、光照、景观和氛围。
4. 每轮表现图都与 SU 基准图对照。若 AI 改动建筑结构，降低自由度或回到 SU 修正视图后重做。

详细流程及可选 RunningHub 兼容方式见 [render-pipeline.md](references/render-pipeline.md)。

## 安全边界

- `su_apply_plan` 在一个事务中执行，失败整体回滚。若响应丢失，用原键、原 plan 和原 revision 重试会得到 `idempotent_replay`；同一键配不同内容会被拒绝为冲突。
- `su_eval` 可能产生未覆盖的副作用。确需使用时必须用 `Su.transaction` 包裹，并立即重新检查修订和模型内容。
- `su_screenshot` 不改模型；`su_capture_views` 与 `su_render` 只能临时改变视觉状态并在结束后恢复。
- 不把零尺寸、顶层松散几何、未命名容器或重复 `spec_id` 留到交付阶段。
- 用户切换模型、手工修改或撤销后，旧 revision 已失效；必须重新 `su_info`/`su_inspect_model`。
